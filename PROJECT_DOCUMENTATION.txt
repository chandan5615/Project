1. DEFINITION OF THE PROJECT AND SCOPE
================================================================================

Sentinel Agent v2.3 is an AI-powered Security Operations Center (SOC) assistant
designed for real-time attack detection and automated response on Linux servers.
The project scope includes monitoring SSH (auth.log) and web server (access.log)
logs, detecting common attacks (SQL injection, XSS, path traversal, brute force),
and automatically blocking malicious IPs with intelligent temporary bans. The system
features progressive punishment (15 min → 2 hours → 24 hours), auto-unblocking with
expiry tracking, and whitelist protection to prevent admin lockout. A secure web
dashboard provides real-time visibility and control. Primary objectives are to
reduce incident response time from minutes to sub-seconds and eliminate manual
effort for common security attacks. Out of scope: packet-level intrusion detection,
custom malware analysis, cloud-specific integrations, and endpoint protection.

================================================================================
2. SYSTEM REQUIREMENT SPECIFICATION
================================================================================

FUNCTIONAL REQUIREMENTS
- Monitor SSH (auth.log) and web (access.log) logs in real time with watchdog.
- Detect common attacks (SQL injection, XSS, path traversal, brute force) and 
  classify severity (LOW, MEDIUM, HIGH, CRITICAL).
- Auto-block attackers with temporary bans (15 min, 2 hours, 24 hours) using 
  progressive punishment based on offense count.
- Auto-unblock expired bans via background cleanup thread (60-second cycles).
- Whitelist protection: auto-detect and protect admin/localhost/local network IPs.
- AI analysis (4-agent CrewAI crew) activated only for HIGH/CRITICAL severity.
- Secure dashboard with bcrypt authentication and session management (24-hour expiry).
- REST API (20+ endpoints) for external integration and control.

NON-FUNCTIONAL REQUIREMENTS
- Performance: Sub-second detection latency, 8-second dashboard refresh.
- Reliability: Docker containers with auto-restart, daemon cleanup thread.
- Security: Role-based access (admin/analyst/viewer), JWT/bcrypt authentication,
  local network-only dashboard binding, iptables firewall integration.
- Compatibility: Ubuntu 20.04+, Debian 11+, Python 3.10+, Docker 20.10+.
- Scalability: Handles 1000+ attacks/day with log rotation and database optimization.
- Availability: Background services, automated deployment (AUTO_INSTALL.sh).

4. EXISTING SYSTEM WITH DISADVANTAGES
================================================================================

- Manual SOC Operations: High labor cost, slow incident response (minutes to hours),
  analyst fatigue, 24/7 staffing required.
- Traditional Firewalls: Static rules, no behavioral analysis, no automatic 
  adaptation, permanent bans risk legitimate user lockout.
- Enterprise SIEM Tools: Expensive licensing ($50K-$500K/year), complex deployment,
  requires dedicated team, overwhelming alert volume.
- Manual Log Review: Time-consuming, error-prone pattern matching, no real-time
  response, difficult to scale across multiple servers.
- Static IP Blacklists: No temporary bans, no progressive punishment, risk of
  permanent admin lockout, requires manual unblock intervention.

================================================================================
5. PROPOSED SYSTEM WITH ADVANTAGES
================================================================================

- Automated real-time blocking with temporary bans (auto-unblock).
- Progressive punishment (15 min, 2 hours, 24 hours) for repeat offenders.
- AI analysis optimized for HIGH severity only (90% resource savings).
- Whitelist protection auto-detects admin IPs, prevents self-lockout.
- Secure dashboard with bcrypt authentication and session management.
- One-command deployment with auto IP detection (no hardcoded addresses).
- Dashboard and API provide clear visibility and control.
- Lower operational cost with consistent policy enforcement.

6. BRIEFING OF MODULES AND FUNCTIONALITIES
================================================================================

- Log Monitoring: Real-time auth.log and access.log monitoring.
- Threat Detection: Pattern matching, anomaly detection, severity scoring.
- Response Engine: Temporary ban/auto-unblock, whitelist checking, progressive punishment.
- AI Analysis: 4-agent crew (Security Analyst, Network Specialist, Threat Intel, 
  Incident Coordinator) - optimized to run only for HIGH severity attacks.
- Dashboard: Secure login, real-time metrics (8-second refresh), IP management.
- REST API: 20+ endpoints for external integration, health monitoring.
- Data Layer: SQLite with blocked_ips (expiry tracking), safe_ips (whitelist), 
  incidents, threat_intel, actions.
- Background Cleanup: Daemon thread checks every 60 seconds for expired bans.

7. METHODOLOGY USED
================================================================================

The project follows Agile development methodology with iterative testing cycles.
Threat detection employs a multi-layer approach combining signature-based patterns,
anomaly detection, and AI-powered analysis. AI resource optimization ensures the
4-agent CrewAI analysis runs only for HIGH severity threats, reducing LLM overhead
by 90%. Testing includes unit tests for individual modules, integration tests for
component interactions, and attack simulation tests (test_attacks.py, continuous_attacks.py)
to validate real-world scenarios. Progressive punishment strategy uses escalating
ban durations (15 min → 2 hours → 24 hours) with automatic expiry and whitelist
protection to prevent admin lockout.
